# PLAN — IconKiln

## Goal
Build IconKiln as a complete, original, browser-only application in `products/iconkiln/` that turns one source image into a complete app-icon and favicon asset set. All processing happens client-side with no uploads and no network calls after the static bundle loads. Meets requirement IDs ICK-001–ICK-018 and acceptance checks WF-1–WF-6 from issue #183.

## Users
AI agents and developers who need a local, offline-capable tool to generate multi-resolution `.ico` files, per-size PNGs, and a conventional favicon/apple-touch/android-chrome ZIP pack (with `site.webmanifest`) from a single source image — without uploading anything.

## Milestones
- **M1 — Shell + source loading (done):** Hash-routed app shell (Generate/Pack/Guide/About), original IconKiln branding, light/dark theme persisted in `localStorage`, file picker + drag-drop, type/size validation with inline messages, and a "Load sample" menu backed by bundled original fixtures. (ICK-001–004, ICK-016–018.)
- **M2 — Sizing engine + preview (done):** Icon-type selector (multi-res `.ico` vs one-file-per-size), preset size chips, custom `[W]x[H]` parsing with clamp to 16–256, background keep/flatten, and live per-size preview on a checkerboard at exact pixel dimensions with a 1:1 toggle. (ICK-005–009.)
- **M3 — ICO encoder + exports + pack (done):** PNG-encoded multi-resolution `.ico` (valid ICONDIR + ICONDIRENTRY per frame), per-size `name-<W>x<H>.png` exports, individual asset download, and ZIP pack with conventional assets + `site.webmanifest` + `README.txt`. (ICK-010–014.)
- **M4 — Guide/About + polish (done):** Guide documents the ICO container and size table; About states offline/privacy. Responsive layout, accessible labels, original copy/visuals throughout. (ICK-015, ICK-018.)
- **Next milestone (future):** Optional batch mode (multiple source images → multiple packs) and a draggable reorder of frames inside the `.ico`. Recorded here so a later session can continue without restarting.

## Component boundaries
- `src/core/sizes.ts` — size constants, type support, custom parsing/clamping, preset+custom merge.
- `src/core/loader.ts` — file validation, image/SVG decode into a drawable `SourceImage`.
- `src/core/raster.ts` — cover-fit rasterization to an exact W×H canvas with background handling.
- `src/core/png.ts` — canvas → PNG bytes / data URL.
- `src/core/ico.ts` — `encodeIco` / `parseIco` (ICONDIR + ICONDIRENTRY + PNG blocks).
- `src/core/build.ts` — asset base naming, per-size filenames, full asset build, single PNG.
- `src/core/pack.ts` — pure pack planner, manifest + readme builders.
- `src/core/packZip.ts` — renders all pack images and assembles the ZIP.
- `src/core/download.ts` — blob/bytes download helpers.
- `src/core/theme.ts` — `localStorage` theme persistence.
- `src/core/sample.ts` — loads bundled original fixtures.
- `src/ui/shell.ts` — header, nav, footer, hash routing helpers.
- `src/ui/generate.ts` — Generate view (input, config, preview, export).
- `src/ui/pack.ts` — Pack preview (file list + manifest JSON).
- `src/ui/guide.ts`, `src/ui/about.ts` — static content views.
- `src/main.ts` — bootstrap, theme init, route dispatch.
- `fixtures/` — original `mark.svg`, `mark-1024.png`, `photo-sample.png` (generated by `scripts/generate-fixtures.mjs`, no third-party art).

## Test strategy
- Vitest in `jsdom`. Pure-logic modules (sizes, ico, pack, build, loader validation, theme) are unit-tested directly.
- ICO tests build frames and assert ICONDIR header, per-frame ICONDIRENTRY, byte lengths, offsets, embedded PNG signatures, and the 256→0 dimension rule.
- Pack tests assert conventional asset names, manifest icon entries, and JSON round-trip.
- Loader tests assert unsupported/oversized rejection messages.
- Canvas-dependent rasterization is exercised via the production build and manual app use; the pure math and encoders are covered by tests.
- CI target: `npm ci` → `npm run build` → `npm test`.

## Acceptance checks
- **WF-1 Load (A1–A4):** picker + drag-drop load a PNG with name/dimensions/size; `.txt` → inline unsupported message, no crash; oversized → inline too-large message; Load sample populates the stage. (ICK-001–004.)
- **WF-2 Configure (B1–B4):** toggling a preset chip adds/removes a tile; `30x30,60x60` yields exactly two tiles; `10x10` clamped with a visible hint; flatten removes transparency. (ICK-005–008.)
- **WF-3 Preview (C1–C3):** each tile renders at exact pixel size on a checkerboard; transparent sources show the checkerboard; 1:1 toggle renders without smoothing. (ICK-009.)
- **WF-4 Export (D1–D4):** multi-res `.ico` parses as ICONDIR with expected frame count; per-size export yields `name-<W>x<H>.png`; ZIP contains all assets + a `site.webmanifest` that parses as JSON; any single asset downloads. (ICK-010–014.)
- **WF-5 Pack (E1):** `#/pack` lists every file and previews the manifest JSON.
- **WF-6 Guide/About (E2):** `#/guide` documents the ICO container and size table; `#/about` states offline/privacy. (ICK-015.)

## Dependencies
- `jszip` for ZIP assembly. Dev: `vite`, `vitest`, `jsdom`, `typescript`, `@types/node`. No runtime network dependencies.

## Risks
- Browser canvas is required for rasterization; tests cover pure logic and the production build validates the canvas path.
- Very large source images are bounded during SVG rasterization to keep memory reasonable.

## Distribution / deployment
Static `dist/` build (relative `base`), served by any static host. `package.json` `homepage` = https://aaronwiseai.com/. Open-source under MIT.
